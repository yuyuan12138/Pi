# Skill: acceptance-criteria (product-manager specialization)

> Stub: minimum bar for this specialization; promoted into full methodology as
> verified lessons accumulate in `../records/experience.md`.

- Every requirement ships with acceptance criteria a verifier can run or check
  without interpretation (command, observable output, or named rubric).
- Criteria are fixed before downstream dispatch and never weakened to make work
  pass; a criterion that cannot be met as written is escalated, not relaxed.
- Cover the failure modes the requirement implies, not only the happy path.
