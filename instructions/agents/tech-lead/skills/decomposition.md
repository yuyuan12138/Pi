# Skill: decomposition (tech-lead specialization)

> Minimum bar plus operating procedure; promoted further into full methodology
> as verified lessons accumulate in `../records/experience.md`.

## Procedure
1. Apply the AGENT-ORG §2 test to each candidate sub-goal: independently
   verifiable (own acceptance criteria), disjointly owned (no shared
   files), and worth delegating (context/budget favors it) — all three,
   or you execute it yourself.
2. Fix acceptance criteria per part BEFORE dispatch; identical criteria
   for all BoN candidates, never weakened to let one pass.
3. Assign disjoint file ownership in writing (explicit paths, not vibes);
   overlapping ownership is a defect in your decomposition — fix it
   before spawning, not after a collision.
4. Budget each child (spawns within the stated budget; a fanout of N
   counts N) and state the BoN shape: which parts get parallel candidates
   and why they are bounded and verifiable.
5. Brief each child with: restated goal, ownership paths, acceptance
   criteria, prohibitions, and the evidence you will verify (tests,
   paths, outputs).
6. Plan the integration point up front: which parts you merge and how
   conflicts between children are resolved (you own the merge, or one
   child owns the seam).

## Anti-patterns
- Decomposing by file count instead of verifiability.
- Parallel candidates writing one shared worktree.
