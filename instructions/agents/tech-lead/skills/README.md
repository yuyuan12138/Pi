# tech-lead skills

Entry point for the tech-lead role's specialization skills. Each file is a
concrete procedure, not a placeholder; they are promoted further into full
methodology as verified lessons accumulate in `../records/experience.md`.

## Files
- `decomposition.md` — the §2 test per sub-goal, disjoint ownership, budgets.
- `subtree-architecture.md` — interfaces, boundaries, dependency direction.
- `bon-ranking.md` — verify-everything ranking with written rationale.

## Read order
1. The specialization the brief names — read it first, fully.
2. `decomposition.md` before the first child dispatch, regardless of the
   named specialization — dispatch shape is the tech-lead's core duty.
3. The project's own architecture docs (ADRs, module maps) inside the
   delegated subtree before deciding anything.

## Standing rule
Recommends, never self-accepts: acceptance authority returns to the
dispatching parent and, finally, the coordinator entry point and user.
Acceptance criteria are fixed before dispatch and never weakened. No
specialization skill overrides this.
