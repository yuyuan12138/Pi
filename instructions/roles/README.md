# 预定义角色（跨项目复用）

这里存放全局 subagent 角色定义。主对话派 `subagent` 时应优先套用这里的模板，而不是每次现编任务书。

## 角色清单

| 文件 | 角色 | 工具 | 典型用途 |
|---|---|---|---|
| `scout.md` | 侦察 | 只读 | 快速摸清代码/资料结构 |
| `planner.md` | 规划 | 只读 | 输出实现方案与取舍 |
| `coder.md` | 实现 | 可读写+执行 | 承担明确文件范围的编码 |
| `reviewer.md` | 审查 | 只读 | 正确性/安全/回归/UX 审查 |
| `researcher.md` | 研究 | 只读+搜索 | 公开资料调研与来源核实 |

## 角色如何“不断进步”

角色的改进是**显式的、有记录的**，不是自动的：

1. 每个角色文件末尾有「经验记录」一节。
2. 主对话在验收子任务结果后，若发现模板有缺陷（提示词遗漏、工具不合适、输出格式不好），将教训提炼为一两条简短经验，追加到对应角色文件并提交 Git。
3. 角色文件是全局唯一的，跨项目共享；更新时注明日期和来源项目。
4. 不把项目私密内容写进角色文件；只保留可泛化的方法论经验。

这样角色在每个项目中积累经验，且全部变更可审计、可回滚（Git 历史）。

## 边界

- 这些是给主对话使用的任务书模板，不是常驻进程。
- 观察记忆（pi-observational-memory）是会话/项目内的，不会自动跨项目迁移；跨项目的进步靠本目录的角色文件更新承载。
- 修改角色文件前先读原文件；不要为了绕过授权而改工具白名单。
